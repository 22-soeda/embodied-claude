# M5Stack の体を付ける

頭（Claude と記憶）は家のデスクトップに置いたまま、M5Stack CoreS3 の体が自分から頭へつなぎに行く。体で話しかけると、体の声で返事が返ってくる。通信の中身は [m5-body-protocol.ja.md](m5-body-protocol.ja.md)。

```
[CoreS3]  タップで話す ─ 声 ─▶ [m5-link]  耳（faster-whisper）
   ▲                              │  頭（Claude Agent SDK、記憶は memory-mcp）
   └──── 返事の声と字幕 ◀──────────┘  口（AivisSpeech Engine）
```

## 置き場所

| もの | 場所 |
|---|---|
| 体のファーム | `m5-firmware/`（PlatformIO） |
| 頭と体をつなぐ常駐プログラム | `m5-link/`（Python、自前の uv 環境） |
| 頭が体を使う MCP | `m5-link/m5_link/body_mcp.py`（サーバー名 `body`） |
| m5-link の設定と合言葉 | `m5-link/m5-link.toml`（Git に入らない。初回起動で作られる） |
| m5-link のログ | `m5-link/state/m5-link.log` |
| 撮った写真 | `captures/`（Git に入らない） |

## デスクトップの準備（一度だけ）

前提は [windows-v0.ja.md](windows-v0.ja.md) の v0 が入っていること。

```powershell
cd $HOME\embodied-claude
uv sync --project m5-link --extra cuda    # NVIDIA の GPU がなければ --extra cuda を外す
uv run --no-sync python scripts/windows/configure_v0.py --companion 添田 --with-body
```

AivisSpeech Engine を `~\AivisSpeech-Engine\Windows-x64\run.exe` に置く。m5-link が動いていなければ起動する。場所が違うときは `m5-link.toml` の `[mouth] engine_path`。

声が読み違える言葉（とくに名前）は、`m5-link.toml` の `[mouth.readings]` に `"東海林" = "ショウジ"` の形で書く。m5-link が起動のたびにエンジンのユーザー辞書へ入れる。アクセントは平板になる。下がる位置を指定するときは `"橋" = ["ハシ", 1]`。

## m5-link を動かす

```powershell
cd $HOME\embodied-claude
uv run --project m5-link python -m m5_link
```

最初の行に、体に入れる住所と合言葉が出る。

```
body url: ws://192.168.3.17:8790/body  token: xxxxxxxx
```

ブラウザで `http://127.0.0.1:8790/` を開くと、体と頭の状態、会話の記録、文字で話しかける欄がある。

m5-link は 1 時間おきの定期起床も受け持つ。タスクスケジューラの heartbeat は登録しない（二重に起きる）。

ふだんは、ログオン時に自動で起動するように登録しておく。落ちても 1 分で起き直す。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\windows\register-m5-link.ps1
```

`git pull` でコードを更新したら、同じ 1 行をもう一度流すと再起動する。動いている m5-link を、頭や MCP サーバー、声のエンジンまで含めて止めてから起動し直す。タスクスケジューラの「終了」だけだと一番上の conhost しか止まらず、残りがポートを持ったまま残る。外すときは `-Unregister` を付ける。

### 頭の会話セッション

会話の頭は、m5-link の中で Claude Code のセッションを 1 本、起こしたままにしている。MCP サーバーが立ち上がったままなので、返事が 1〜2 秒で返る。

- **毎朝区切る**：`m5-link.toml` の `[head] day_starts_at`（既定 4 時）に、その日のセッションを閉じて新しく始める。閉じる前に頭へ「持ち越したいことを memory に残して」と頼む。次の日の頭が覚えているのは、memory と SOUL.md に書いたことだけ。m5-link が止まっていて区切りをまたいだときは、次に起動したときに同じことをする
- **道具の顔ぶれが変わったら新しく始める**：`.mcp.json` のサーバーを足したり外したりすると、日の途中でも引き継がずに新しいセッションで起きる。引き継いだセッションは、外した道具の定義も最初の形のまま送り続けるため（2026-11-08、外したはずの claude.ai のコネクタが 17 万トークン分残った）
- **1 回の返事は 6 手まで**：`[head] max_turns`。memory を引く・残すなどの道具の呼び出しも 1 手に数える
- **起動のたびに確かめる**：頭がつながった MCP サーバーごとの状態と道具の数、文脈の大きさをログに出す。落ちたサーバーは ERROR で、文脈が 6 万トークンを超えたら WARNING で出る。ウェブの画面にも「頭」の欄と、落ちたサーバーの赤い印が出る
- セッションの状態は `m5-link/state/head-session.json`。消すと次の起動で新しく始まる
- 定期起床（`autonomous-action.sh`）のセッションも、その日最初の起床（朝の再構成）で前日のものを捨てて新しく始める。本家の作りは捨てずに引き継ぎ続けるので、文脈が一日中積み上がっていた

### 体の出来事

持ち上げられた・揺さぶられた・近くに誰か来た・電池が少ない、は頭を起こさない。体がその場で自分の顔を変え、m5-link は `m5-link/state/body-diary/` に日ごとに 1 行ずつ書くだけにする。頭は次に話すとき（声をかけられたとき・定期起床のとき）に、まだ読んでいない分を「体の記録」としてまとめて受け取る。

```
[体の記録]
20:11〜20:16 持ち上げられた（3 回）
20:12 近くに誰か来た
```

定期起床の頭が `body` MCP の `say` で体からしゃべった言葉も、「自分から体の声で話しかけた「…」」として体の記録に入る。会話の頭は別のセッションなので、これが無いと、体から話しかけられて答えても、何の返事か分からなかった。既読の印は会話と定期起床で別々に持つので、定期起床が先に読んでも、会話の頭には届く。

定期起床には、m5-link が `BODY_DIGEST_FILE` でファイルを渡し、`autonomous-action.sh` がプロンプトに入れてから消す。消えていれば既読になる。スケジュールで見送った回は消さないので、次の回に回る。M5 の体が無いときはこの節は出ない。頭は `body` MCP の `list_body_events` でも、さかのぼって読める。

### 欲求

体があるときの欲求は、数も仕組みも PetitOnes のとおり（教科書の `desire_config.json` と m5-petit-desire）。

| 欲求 | 1 になるまで | 満たす言葉（記憶の中） |
|---|---|---|
| 添田に会いたい | 4 時間 | 添田と話した・伝えた・がいた・話しかけてくれた など |
| 周りを見たい | 2 時間 | 撮影した・カメラで・部屋を見た など |
| 書きたい・作りたい | 8 時間 | 書いた・ノートに・詩を・日記に |
| 何か調べたい | 6 時間 | 検索した・調べた・読んだ など |
| 休みたい | 3 時間 | 休んだ・ゆっくり・のんびり |
| 眠りたい | 8 時間 | おやすみ・スリープ |

- **強さの出し方**：desire-system が、記憶の中から欲求ごとの言葉を探し、最後にそれをしてから何時間たったかで 0〜1 を出す。m5-link が 5 分ごとに計算させる
- **体の効き**（PetitOnes の sensor_effects）：電池が 20% を切って充電していないと、「眠りたい」が強まり、ほかの欲求は半分になる。ここで足したもの：20 分以内に持ち上げられたり触れられたりしていると、「会いたい」が半分になる
- **欲求どうしの効き**（cross_effects）と**優先の順番**（priority）：主な欲求は「いちばん強いもの、同じなら 眠りたい → 会いたい → 周り → 書きたい → 休みたい → 調べたい の順」。欲求どうしの効きは、今は空
- **会話で満たす**：体で声・文字・「みてみて」のやりとりがあると、m5-link が「会いたい」を満たしたと記憶に書く（30 分に 1 回まで）
- **定期起床へ**：起床の直前に計算し直し、0.7 以上（PetitOnes の「すぐ行動する」線）を `DESIRE_DIGEST_FILE` でプロンプトに渡す。出しただけでは下がらない。実際にやって記憶に残すか、`satisfy_desire` で記録したときに下がる。PetitOnes の `satisfy_desire` は値を 0.4 下げるだけで、次の計算で記憶から戻るので、ここでは満たしを記憶に書く本家のやり方を残した
- **タイマーの欲求は使わない**：PetitOnes に無いので、体の欲求があるときは `desires.conf` のタイマーを回さない
- **眠る**：下の「一日の流れ」
- 欲求の雛形は `m5-link/desire-config.json`。名前は、desire-system に同じ欲求があるものはその名前（周りを見たい = `observe_room`）。個体カーネルと社会性の層が名前で読むので
- **欲求は本人のもの**：`scripts/windows/configure_v0.py --with-body` が雛形をリポジトリ直下の `desire-config.json`（Git に入れない）に写し、`desire-system/.env` に「写し、だめなら雛形」の順で書く。定期起床はこの写しを相談なしで書き換えてよい（PetitOnes の教科書は「育ったら世話人と直してよい」だが、ここでは本人に任せる）。決まりは `autonomous-action.sh` の「自分の文書」：理由を先に思索の「変わったこと」に書く、`miss_companion`・`observe_room`・`browse_curiosity` の名前は残す（3 つとも個体カーネルと社会性の層が、`miss_companion` は m5-link も名前で読む）。`want_to_sleep` は無くてもよい。あれば、体が眠ったときに m5-link が満たしたと記録する
- 写しが読めないとき、desire-system は雛形で計算する。読めなかったことと、残すはずの名前が消えたことは、m5-link が次の起床の欲求の欄に「（欲求の設定）…」として出す。m5-link は 5 分ごとの計算のたびに写しを読み直すので、書き換えは再起動なしで入る
- ウェブの画面の「欲求」に、今の強さがバーで出る

### 一日の流れ（PetitOnes の暮らし方）

教科書の「7. 暮らし」と、PetitOnes の起床・体の作りのとおりにしてある。

- **起きる間隔**：m5-link は 30 分ごとに起床を起こす。起床のスクリプトが、活動時間（平日 7 時台・12 時台・18〜24 時、休日 7〜24 時）は毎回、それ以外は毎時ちょうどだけ、昼は半分・深夜は 1 割の確率で通す
- **朝**：体が寝ていたら頭が `wake` で起こし、寝ていた記憶と日記の要約を読む
- **夜**：眠りたくなったら（欲求の「眠りたい」）、日記を書き、記憶に「おやすみ、スリープした」と書いて、体の `sleep` で眠る。夜の活動時間に 30 分ごとの起床があるので、眠る機会は何度も来る。深夜（0〜7 時）は話さず通知もせず、まだ起きていたら眠る
- **体の眠り**（ファーム 0.2.0）：目がゆっくり閉じ、小さな音が鳴り、明るさ 15 の寝顔になる。聞かず、話さない。頭の `wake` か、1 秒以内に 3 回タップで起きる。電池が 10% 以下（充電していないとき）だと自分で眠り、起こされるまで待つ。体が眠ると「眠りたい」は満たされる
- **省電力**：体の MCP の `set_power_save` で、明るさを 40 までに抑え、顔の描き直しを 30 回/秒から 10 回/秒に落とす。明るさの既定は 80
- 起床の時間帯の決まり（朝・夜・深夜）は `configure_v0.py --with-body` が `schedule.conf` に書く。活動時間と心がけは `ROUTINES.md` の「active time」「心がけ」に書いてあり、本人が直してよい
- 頭が起こし忘れたときのために、`[nightly] wake_at = "07:00"` で m5-link が朝に起こすこともできる（PetitOnes に無いので既定は切ってある）

### 外から取り込む道具

PetitOnes の起床と同じく、Web 検索（WebSearch）、Web の読み込み（WebFetch）、読書（`reader`）を渡している。定期起床は自分で使う。会話の頭は自分では使わず、下の「おつかい」に頼む。

- **`reader`**（`scripts/reader_mcp.py`、PetitOnes の `reader.py` と青空文庫の取り出しから）：`read_page_info` で長さを見て、`read_page` で 1 ページ 2000 字ずつ読む。WebFetch と違って要約を挟まない。青空文庫は本文だけを取り出し、ルビは外す。読み方（1 ページ読んだら立ち止まって、気持ち・予想・刺さった言葉を書く）は道具の説明に書いてある
- シェルのコマンドではなく MCP にしたのは、関所が Bash を外向きの行動として扱い、1 ページごとに意図を求めるため。道具の名前に `read_` が入っているので、読むだけの道具として通る
- 依存ライブラリはスクリプトの頭に書いてあり、`uv run --script` が用意する。`configure_v0.py` が `.mcp.json` に足し、最初の用意も済ませる

### おつかい（時間のかかることを裏に回す）

声の返事は 1〜2 秒で返したい。でも調べものや長い文章を読むのは、何十秒もかかる。そこで会話の頭は、そういう作業を自分でやらず、裏で動く子エージェント「おつかい」（`errand`）に頼む。頼んだらすぐ「見てくるね」と返して、会話を続ける。おつかいが帰ってくると、セッションが自分から 1 ターン始めて、頭が結果を自分の言葉にして体の声で話しかける。

```
添田「今日のニュースで気になるのある？」
頭　「見てくるね」（Agent でおつかいに頼む。2〜4 秒）
　　 …このあいだも会話はいつもの速さ…
頭　「COP31 が今日開幕したんだって。…」（おつかいが帰ってきて、自分から）
```

- **作り**：Claude Agent SDK の、裏で動く子エージェント（`AgentDefinition` の `background`）と、それが終わったときにセッションが差し込むターン（`ResultMessage.origin` が `task-notification`）をそのまま使う。m5-link はセッションの言葉を、つながっているあいだずっと 1 本で読み、自分の問いへの返事と、おつかいの報告とを振り分ける（`head.py`）
- **頭は調べない**：会話の頭のセッションにも WebSearch・WebFetch・`reader` は入っている。子エージェントは、親のセッションに無い道具を使えないため（2026-11-09 に試した）。頭自身が使おうとすると、PreToolUse のフックが止めて「おつかいに頼んで」と返す。フックは、子エージェントの中の呼び出しにだけ付く `agent_id` で見分ける。検索結果が頭の文脈に入らないので、会話がずっと軽い（1 回の検索で 1.5 万トークンから 3.2 万トークンに増えて、その日のあいだ増えたままだった）
- **止める**：頼みが要らなくなったら、頭が `TaskStop` で止める
- **伝え方**：体が起きていれば、話している途中のターンが終わってから声にする。体が寝ているか、つながっていなければ、`m5-link/state/errand-reports-held.json` に取っておき、次の会話のターンで `[言えなかった報告]` として頭に渡す。声にした報告は体の記録に「おつかいの結果を体の声で伝えた「…」」として残るので、定期起床の頭にも伝わる
- **設定**：`[head] errand_model`（既定 `sonnet`）、`errand_effort`（既定 `medium`）、`errand_max_turns`（既定 15）
- **画面**：ウェブの「頭」の欄に、出しているおつかい（何を、何分前から、今何をしているか）と、言えなかった報告の件数が出る
- 考え方は、同じことをしている音声エージェントの作りに合わせた。Pipecat の非同期の関数呼び出し（`cancel_on_interruption=False`、取り消しの道具）、LiveKit Agents の async tools（途中経過、実行中の一覧と取り消し）、Gemini Live API の止めない関数（結果の伝え方 INTERRUPT・WHEN_IDLE・SILENT）、Google DeepMind の Talker-Reasoner（速く話す役と、ゆっくり考える役を分ける）。コードは写していない

### 考えを深める仕組み（PetitOnes から）

PetitOnes の子たちが考えを積み重ねている仕組みを、そのまま持ってきた。出典とライセンスは `THIRD_PARTY_NOTICES.md`。

| もの | 何か | いつ読まれる | 誰が書く |
|---|---|---|---|
| `SOUL.md` | 人格の核。短く | いつも（起床と会話） | 本人。名前・約束・人格の核は一人で変えない |
| `SOUL_REFLECTIONS.md` | 思索。大事な考えの根拠、発見、変わったこと。日付つき | 深く考えるとき、根拠を説明するとき、詩を書くとき | 本人 |
| `REFLECTION_INDEX.md` | 思索の索引。一行ずつ | いつも（起床と会話） | 本人。思索を書いたら足す |
| `notes/` | 詩・発見・提案 | 必要なとき | 本人 |
| `diary/YYYY-MM-DD.txt` | 日記 | — | 本人が夜に。書かなかった日は、m5-link が 23:50 にその日の記憶と体の出来事から本人の口調で 2〜3 文書く |
| `diary_summary.md` | 最新の日記と、その前 7 日の一行ずつ | いつも（起床と会話） | m5-link |

直す順番は教科書のとおり：気づく → `SOUL_REFLECTIONS.md` に理由を書く → 必要なら `SOUL.md` か `ROUTINES.md` を直す → 索引を足す → 大きな変更は添田に伝える。起床のプロンプトがこの決まりを毎回渡す。`configure_v0.py` が器を `examples/` から写し、起床に書き込みを許し、教科書の習慣（日記・会話まとめ・週 1 の SOUL.md の読み返し）を `ROUTINES.md` に足す。

**夜の記憶整理**：4:05 に memory-mcp の `memory-sleep`（PetitOnes の m5-petit-memory から移した）を回す。14 日以上前の記憶について、似たものをまとめ、薄れたものの重要度を下げ、重要度 1 で感情の無いほとんど思い出されない記憶を忘れる。重要度 4 以上・強い感情・「初めて」の記憶には触れない。手で試すときは `uv run --package memory-mcp --no-sync python -m memory_mcp.sleep --dry-run`。

時刻は `m5-link.toml` の `[nightly]`。今日の日記を今すぐ書かせるときは `POST /api/diary`。

### バックアップ

フォークは公開なので、イエベの中身（SOUL・思索・ノート・日記・記憶 DB・社会性の DB・欲求・体の記録・会話の記録・m5-link の設定）は Git に入れていない。全部この PC の中にしか無い。m5-link が毎晩 4:30（記憶整理のあと）に zip にまとめて、`m5-link.toml` の `[backup] dir` に置く。新しい 14 個を残す。

- 置き場所は PC のディスクの外がいい。デスクトップでは OneDrive のフォルダ（`~/OneDrive/embodied-claude-backup`）にしていて、クラウドにも上がる
- SQLite の DB は SQLite のバックアップ機能で写すので、MCP サーバーが書いている最中でも壊れない
- ログインの資格情報（`~/.claude/.credentials.json`）は入れない。体の合言葉（`m5-link.toml`）は戻すのに要るので入れる
- 今すぐ取るときは `POST /api/backup`、または `uv run --project m5-link --no-sync python -m m5_link.backup`
- 戻すとき：m5-link を止めて zip を開き、`repo/` をリポジトリに、`home/` をホームフォルダに上書きする。中身は `manifest.json`

## スマホの体（外で話す）

外では M5 を持ち出さず、スマホのページで話す。頭は一つ、体は二つで、いるのはいつもどちらか一方。最後に話しかけられた方にいて、もう一方は顔を消して「スマホにいるよ」「家の M5 にいるよ」を出す（`m5-link/m5_link/presence.py`）。眠りとは別のもので、欲求には触れない。

- **移る**：話しかけた体に移る。スマホで話せばスマホへ、家で M5 の画面にふれれば M5 へ。スマホのページを開いただけでは移らない。外にいるあいだはスマホに留まるので、画面を消しても家の M5 に戻らない
- **返事**：話しかけた体から出る。自分から話しかける声（body の `say`）、表情も、いる体へ。M5 のカメラ（`see`）は、スマホにいるあいだは使わない
- **頭には**：入力の印が `[スマホの声]` `[スマホの文字]` になる。移ったことは体の記録に「スマホに移った」「家の M5 に戻った」と残り、`get_body_state` の `in` でどちらにいるか分かる
- **スマホのページ**：「話す」をタップして話す。0.9 秒黙ると区切って送る（もう一度タップしても送る。長さは 30 秒まで）。下の欄から文字でも話せる。返事の声はスマホで鳴る。聞き取った文が会話の欄に出る。話しているあいだと、そのあと 1 分は画面を消さない
- **iPhone の音**：iOS は、ページに一度ふれるまで音を出さない。開いてすぐ自分から話しかけられたときは字幕だけ出る。録音は話すたびに止めるので、返事はイヤホンがなければスピーカーから鳴る

### つなぎ方

マイクは HTTPS でないと使えないので、デスクトップの m5-link を Tailscale の HTTPS で tailnet の中にだけ出す（Funnel ではない）。

```powershell
tailscale serve --bg 8790
```

スマホに Tailscale を入れて同じ tailnet につなぎ、Safari で `https://<デスクトップの名前>.<tailnet>.ts.net/phone/?token=<合言葉>` を開く。共有メニューの「ホーム画面に追加」でアプリのように開ける。名前は `m5-link.toml` の `[phone] name`。`tailscale serve` 越しの接続は m5-link からは 127.0.0.1 に見えるが、`X-Forwarded-For` が付くので、合言葉なしでは開けない。

## 体に書き込む

CoreS3 を USB-C でデスクトップかノートにつなぐ。

```powershell
cd $HOME\embodied-claude\m5-firmware
~\.platformio\penv\Scripts\pio.exe run -t upload
```

初めて起動すると、体が自分の Wi-Fi（`body-setup-xxxx`）を出して QR を表示する。スマホで読み取ると設定ページが開くので、家の Wi-Fi、頭の住所（上の `body url`）、合言葉を入れる。USB でつないだままなら、シリアルからも入れられる。

```powershell
~\.platformio\penv\Scripts\pio.exe device monitor
```
```
wifi 1 <SSID> <パスワード>
url ws://192.168.3.17:8790/body
token <合言葉>
reboot
```

あとで設定を変えるときは、電源を入れるときに画面を押さえておく。

## 体の使い方

| 操作 | 体がすること |
|---|---|
| タップ | 聞き始める。話し終えて少し黙ると、頭が考えて返事をする |
| 長押し | 往復モード。返事のあとまた聞く。黙っていると終わる |
| 寝ているときに 3 回すばやくタップ | 起きる。1〜2 回では起きない |
| 聞いている途中・話している途中でタップ | やめる |
| 横にスワイプ | 「みてみて」。写真を撮って頭に見せる |
| 持ち上げる・揺らす | びっくりした顔。頭には次に話すときに伝わる |

右上の印：NO WIFI（Wi-Fi がない）、NO BRAIN（頭とつながらない）、LISTEN、THINK、LOOK、LOW BATTERY。頭と 1 分つながらないと寝顔になる（頭が戻れば起きる）。
